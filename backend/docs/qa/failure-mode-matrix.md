This Stage 5 Batch 2 matrix was prepared at starting commit `c5d6f084f29c6aae7445bd96cccef8b205041230` on `kavia/cmada08852`. The matrix covers all 20 operations on 17 paths in the [inventory](endpoint-inventory.md). The [API matrix](api-test-matrix.md) supplies per-operation positive, negative, boundary, schema, header, and AC expectations. This companion focuses on authentication, validation, conflict, concurrency, stale state, dependency failure, and renderer failure. No code/test changes, commit, or push are authorized by this batch.

## Outcome oracle and evidence notation

`U`, `S`, `P`, `WU`, `WP`, `RU`, and `RP` expand to the exact pytest file prefixes defined in the [API matrix](api-test-matrix.md#how-to-read-evidence-and-acceptance-references). A reference such as `RP:test_retirement_http` means `tests/test_reporting_postgres.py::test_retirement_http`, relative to `backend/`. Test function names below are exact; parametrized scenario descriptions do not invent node suffixes.

All failures require `application/problem+json`, `Cache-Control: private, no-store`, and safe `Problem` fields `type`, `title`, `status`, `code`, with optional safe `field_errors` omitted when absent. No submitted evidence, password, token, SQL, or exception text should be exposed. Failed commands leave all applicable rows, parent/type revision, and event counts unchanged; failed exports return no PDF bytes or success attachment output. Error ETags/current revisions are not promised. Exact full wire assertions remain G01 where referenced tests do not assert every field.

`Existing` means evidence found in source, not a pass this batch. `Partial` distinguishes service/unit evidence from HTTP guarantees and separates broad status assertions from exact contract assertions. Gap IDs resolve to the API matrix's genuine gap register; they are proposed verification work, not new tests created here.

`AC-xx` means a Stage 1 criterion. `Support DR-03` and `Support LLD-8` identify authorization or technical-contract support where no direct endpoint AC exists. Backend-only evidence does not complete UI or product acceptance.

## Traceable implementation boundaries

The safety findings follow concrete code paths rather than generic API assumptions. In [workflow.py](../../qualitytrack/workflow.py), parent resolution/locking and command-specific gate checks precede transactional writes; the quoted revision parser is shared by transitions and retirement. The [workflow router](../../qualitytrack/workflow_routes.py) returns ETags only after successful service results and deliberately converts duplicate If-Match headers into a malformed token for normal authorization-first handling.

In [reporting.py](../../qualitytrack/reporting.py), type retirement uses capture's type-lock protocol, and overdue continuation binds the evaluation date/zone while querying live work. In [evidence.py](../../qualitytrack/evidence.py), `export_record` obtains a complete detached snapshot, renders outside the read transaction, and reloads final identity/grants before returning complete bytes. [Reporting routes](../../qualitytrack/reporting_routes.py) construct PDF media/attachment success only after that service returns. The [main application](../../qualitytrack/main.py) and [Problem handling](../../qualitytrack/errors.py) distinguish expected domain failures, framework validation, SQLAlchemy dependency failures, and generic internal failure.

These paths justify the expected outcomes; they do not substitute for the missing injected HTTP assertions. In particular, a post-flush rollback test is not a503 response test, a renderer method throwing on a glyph is not an HTTP failure test, and OpenAPI schema-reference resolution is not live-response schema validation.

## Approval boundary and exclusions

The actual remaining work is limited to G01–G10 in the companion API matrix: wire-contract assertion extensions, selected HTTP authorization/not-found/input boundaries, missing accepted text boundaries, future/reopened overdue reconciliation, PDF isolation/reserved evidence, service-to-HTTP final-auth/partial-output bridges, dependency failures, and malformed signed child-cursor payloads. Existing locking, rollback, schema declarations, long-PDF layout, lifecycle cycles, and calendar pinning must be retained rather than rebuilt.

AC-01c UI retention, AC-03c/03e UI prompts, AC-01b/01d photo support, AC-02b conditional rules, and AC-06/07 analytics are not accepted by this backend-only batch. Full AC-08a/08c product acceptance remains broader than the settled photo-free Latin renderer. AC-04f forbids treating completion as verified effectiveness. Production identity/grants/calendar policy, performance, accessibility, and rollout authorization remain separate decisions.
